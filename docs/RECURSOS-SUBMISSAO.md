# Radiance — Space Apps Submission Resources

Documentation audit: **2026-11-15 (America/Sao_Paulo)**, against the local `main` implementation. This inventory maps to the two resource sections in the NASA Space Apps submission form. It is not evidence of agency endorsement, clinical validation or a flight-ready system.

The audit includes the team narrative added upstream in `e854bf7` during the review. Its Figma presentation link and Claude declaration are attributed to the team; external presentation contents and undocumented AI task/model details were not independently established.

Use **Link Text** and **Link URL** as the form entry; keep **Classification** and **Project Usage** with the description so references are not presented as imported datasets. Evidence paths are relative to the repository root. Collection periods, timestamps, quantities, units and historical counts are recorded in [Scientific Data Used](DADOS-NASA-UTILIZADOS.md).

- **Integrated:** a specific scientific product has a collector, parser, contract, tests and documented collection records. Collection is manual; API polling does not contact the external provider.
- **Scientific Reference:** a documented contribution to terminology, limitations or design reasoning, not a chart data source or an implemented risk model.
- **Development Tool:** software, platform or development/visual resource demonstrably used in the project. This label does not turn development tools or AI-generated assets into scientific evidence.
- **Future Research** and **Not Used** resources are excluded from the submission tables. They remain distinguished in [Scientific Sources](FONTES-CIENTIFICAS.md).

### Attribution and submission checks

- Keep NASA/NOAA/CSA and model/instrument contributor attribution. Public access is not a blanket license or endorsement; consult product terms before redistributing data or imagery. [CCMC SEP Scoreboard rules](https://ccmc.gsfc.nasa.gov/scoreboards/sep/) and [DONKI publication/disclaimer guidance](https://ccmc.gsfc.nasa.gov/tools/DONKI/) apply to their products.
- Scientific observations, forecasts, official bulletins, catalog events and simulated data are distinct. Forecast probabilities are not injury probabilities. Proton flux is not a personal dose; µGy/h cannot be relabeled µSv/h.
- No physical smartwatch, radiobiological model, PostgreSQL deployment, Cloudflare deployment or automatic external collection is claimed. Figma presentation use and Claude use are team-declared, not scientific integrations. No definite portrait-generation model was found. Retained `components.json`/legacy UI helpers do not establish current use of the shadcn generator, so it is not listed as an actively used tool.
- Technical/source entries above are prepared for copying into the form, not submitted automatically. Screenshot/asset URLs target `main`; the new documentation file will only become visible remotely after an explicitly authorized push. Image-model attribution remains explicitly unknown; do not invent a provider to complete the form.
- Links were checked during this audit; transient errors are not proof that a source no longer exists. The official challenge page is identified separately in [Scientific Sources](FONTES-CIENTIFICAS.md), with its direct-access verification limitation. Do not add future datasets to the integrated list to fill the form.
- The team-provided Figma presentation URL responded with HTTP 200, but this does not certify its contents or anonymous sharing permissions. The Space Apps 2026 and participant-terms links in the team narrative also encountered certificate errors and need a final check by the submitter; no security setting was bypassed.
- Link corrections: SWPC institutional pages now use their verified `www.spaceweather.gov` destinations; OSDR uses its official redirected portal, and Uvicorn uses the current documentation address `uvicorn.dev`. The redundant MSL/RAD `data.nasa.gov` mirror could not be verified and was removed in favor of the existing checked CDAWeb link. The OpenAI Codex page was confirmed through web retrieval despite a 403 response to the direct automated check. The bare DONKI API endpoint requires an `api_key`; the documented historical query with public `DEMO_KEY` responded successfully. No private key was used or recorded.

Audit validation covered 10 Markdown documents, 48 relative links (including five images), 28 table structures and 104 explicitly named inventory evidence paths, with no missing local targets or table-column errors. Of 84 distinct external URLs checked, 78 returned successful HTTP responses in the final direct pass; CSA Radi-N2 and OpenAI Codex were confirmed through web retrieval after direct failures, the bare DONKI endpoint required its documented key parameter, and three Space Apps addresses retained the certificate/gateway caveat above. Application builds/tests, scientific collectors and database writes were not run.
